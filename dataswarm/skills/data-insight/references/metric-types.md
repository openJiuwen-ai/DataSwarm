# 指标类型判定

传给 `dim_breakdown` 的 `metric_kind` 决定跑哪些自洽校验。**判错会导致持续误报或漏报。**

---

## 三类指标（可加性维度）

| 类型 | 判据 | 例子 | 各维度之和 = 总量？ |
|---|---|---|---|
| **additive**（默认） | 在当前粒度、分组与范围内求和有意义，分组无重叠 | 非重叠事件的订单量、金额、次数 | ✅ 在上述前提下成立 |
| **ratio** | 由分子与分母之比定义，跨组需重算各自口径 | 转化率、成功率、客单价、人均 | ❌ 不成立 |
| **distinct** | 含去重 | UV、DAU、去重用户数、活跃商家数 | ❌ 不成立 |

按发布定义、实际粒度与分组关系判断：当前分组的值相加是否等于同口径总量？同一指标可能跨某些维度可加、跨时间不可加；指标名称本身不能证明可加性。

---

## 例：去重指标各维度之和大于总量

实测数据（77,941 行订单的演示库）：

```
全国 distinct user  = 11,975
各地区之和          = 41,313      比全国多 29,338
```

一个用户在广东和北京都下过单，在省维度被算两次、在全国只算一次。
因此对 UV、DAU 这类指标要传 `"metric_kind":"distinct"`，加和类断言会自动跳过。

---

## 各类型跑哪些校验

| 校验 | additive | ratio | distinct |
|---|---|---|---|
| 份额闭合（Σ\|gross_share_pct\| = 100%） | ✅ | ❌ 跳过 | ❌ 跳过 |
| 净变动闭合 | ✅ | ❌ 跳过 | ❌ 跳过 |
| 净占比闭合（`net_share_reliable` 为 true 时） | ✅ | ❌ 跳过 | ❌ 跳过 |
| 每个成员的变动可重算 | ✅ | ✅ | ✅ |
| 最大偏离不小于离散度 | ✅ | ✅ | ✅ |

## 率型指标的处理

率型指标按维度拆“率的变化”没有可加性，可按问题选择以下方法；分子与分母也须分别判断可加性，去重分母不能直接跨组累加。

**① 拆成两个可加指标分别拆解**

```sql
-- 事件表每行代表一次访问，converted为该访问是否转化的0/1标记
-- 上游取数或已有证据计算产出分子、分母；先核对真实数据是否符合此前提
SELECT ds, region, SUM(converted) conversions, COUNT(*) visits
FROM events GROUP BY ds, region
```

可分别检查 `conversions` 与 `visits` 的变化。分别拆解两者只能解释其各自变化，不能将两份贡献直接当作整体转化率的贡献。

**② 用公式拆解**

问题存在已确认的业务恒等式时，可用 `formula_breakdown`。例如销售额由访客数、转化率和客单价构成时，先核对转化率的分子与客单价的分母能否衔接：

```
GMV = 访客数(visitors) × 转化率(conv_rate) × 客单价(aov)
```

```bash
python analyzer.py formula_breakdown \
  --params '{"baseline":{"visitors":86000,"conv_rate":0.031,"aov":158},
             "current":{"visitors":82000,"conv_rate":0.022,"aov":160},
             "expression":"visitors * conv_rate * aov"}'
```

它会给出降幅里有多少来自流量、多少来自转化、多少来自客单价，
这是按维度拆解给不出的。默认用精确 Shapley 分解，各因子 `effect` 之和等于净变动。

## 常见误判

| 指标 | 容易误判为 | 实际 | 说明 |
|---|---|---|---|
| 客单价 | additive | **ratio** | = GMV / 订单数 |
| 人均时长 | additive | **ratio** | = 总时长 / 用户数 |
| 活跃用户数 | additive | **distinct** | 跨维度会重复计数 |
| 订单金额 | ratio | **additive** | 每单一个金额，直接可加 |
| 商品数 | distinct | 看定义 | SKU 去重数是 distinct；销量是 additive |

类型不明确时查指标定义与实际粒度；仍无法确定则保留未知，避免使用依赖可加性的结论，不通过改成 distinct 跳过校验。

## 周期聚合方式（与可加性正交的另一个维度）

周期聚合由用户问题与指标定义决定，不能仅凭指标名选 SUM、AVG 或期末值：

| 聚合类型 | 判据 | 例子 | 周期内取法 |
|---|---|---|---|
| **事件总量** | 周期不重叠、口径一致 | 订单量、销售额 | 跨期可加时求和 |
| **比率** | 周期整体分子与分母之比 | 转化率、点击率、客单价 | 先按定义计算周期分子与分母，再相除；不默认平均每日率值 |
| **日均水平** | 问题明确要求每日数值的均值 | 月内日均活跃用户数、平均每日余额 | 对定义一致的每日观测求均值，说明缺失日期的处理 |
| **时点存量** | 问题要求某时点的状态 | 期末库存、期末余额 | 选择对应时点快照，披露快照缺失或滞后 |
| **周期去重规模** | 期间内实体去重 | 月活跃用户数 | 按整月去重或使用定义匹配的月度指标，不能累加每日去重数 |

“本月 DAU”可能指日均、每日走势或某日数值，依据上下文选择并说明；不能把每日活跃数之和称为月内去重用户数。MAU也可能是自然月或滚动窗口口径，不能统一当期末存量。仅有每日率值而无所需权重，或仅有每日去重数时，不能假装已算得周期整体指标；说明缺项，必要时澄清。
