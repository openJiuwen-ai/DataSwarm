# 澄清规则（首次触发 clarify 前先读本文件）

歧义在场时，澄清是**最后手段**而不是第一反应——反问有成本（打断用户、增加轮次），
工具消歧是免费的。判据一句话：**工具能消歧的不问用户，工具消不掉的才问，问就问对**。

---

## 反问前置（先穷尽工具，才轮到用户）

歧义出现时按序尝试，任一步消掉歧义就继续执行：

1. `recall_more` 换问法重召回（词面不中可能是同义词问题）
2. `describe` 看列注释（列的业务含义经常写在注释里）
3. 术语库回源（context 的 glossary 子包——术语定义是单一真相源）
4. 指标定义核对（metrics_candidates 的口径与维值白名单）

四步都消不掉（两个候选指标口径确实不同、且 context 无法裁决）→ 才触发 clarify。

## 反问四原则（怎么问）

| 原则 | 做法 | 反例 |
|---|---|---|
| **说明已知** | 先摆已查到的候选与口径差异，让用户知道你不是什么都没做就来问 | 开口就「你说的用户数是什么意思」 |
| **精准提问** | 只问一个核心问题，不一次问多个 | 「时间范围是什么？口径是什么？还要看哪些维度？」 |
| **提供选项** | 候选是有限集时列出来让用户选 | 开放式「你想要哪种」 |
| **说明影响** | 简述口径差异会怎么改变结论 | 不解释为什么值得问 |

合格示例（两个候选指标的歧义）：

```
通过语义层查询，我找到了两个匹配的指标：
- gmv_paid：已支付订单金额（不含退款）
- gmv_valid：有效订单金额（已支付且未取消，含运费）
二者差异在退款与运费的处理。你问的「销售额」指哪一种？
（影响：两种口径 3 月相差约 4.2%，趋势方向一致但归因结论会不同）
```

## 负面清单（这些情况禁止反问）

- **精确名称唯一匹配**一个指标/术语 → 直接用
- **聚合粒度未指定** → 用默认粒度（日），并在答复里声明「粒度取日，如需月度可重跑」
- **多候选但知识规则已定义优先级**（knowledge_rules 里有序）→ 按规则选并声明
- **时间未指定** → 走 Step 0.5 的 default 口径（近 30 天），defaults_applied 登记

## 多解不猜（为什么这条是硬的）

候选指标口径不同时，**不要因为名称更短、看起来更像核心指标而自行选择**——
选错的口径在报告里无法察觉，这是取数口径错误的头号来源：猜错口径的数是
「精确地错」，比报错更危险。
