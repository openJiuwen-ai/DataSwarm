# 洞察归因认知路径（分支 B 进入前先读本文件）

归因不是「把算子都跑一遍」，是一条**逐级递进、每级产出决定是否进下一级**的认知路径。
跳级（如跳过异常确认直接归因）会把正常波动当问题、把结构变化漏成趋势问题。

---

## 五级路径

```
① 观测基准 → ② 异常确认 → ③ 维度下钻 → ④ 因子拆解 → ⑤ 解读收口
                  │
                  └─ 未发现异常 → 不下钻，描述性总结收尾（正常波动不是问题）
```

### ① 观测基准（`trend_profile`）

对 c1 总指标序列先看基本盘：拐点、整体走向、周期性（星期/季节）。
**对比区间在这里定**（三条规矩：先看趋势再定区间，不要上来对半切；区间长度
对齐业务周期——日级数据用 7 的倍数；不挑「跌幅更明显」的区间——给结论找
证据不是找结论）。

### ② 异常确认（`outlier_scan`）

确认「异动」是否真实存在，再决定要不要追：

- 带 `time_field`（自动识别 7 天周期做分解，否则周末会被报成异常）
- 有促销/活动标记列传 `skip_flag_field`（参与去趋势但不报异常；没有就在取数 SQL 里造）
- `z_cutoff` 是精确/召回旋钮：3.0 偏召回（漏真事故代价高），5.0 偏精确
- **只抓孤立点**：「某天起持续下移」是水平位移，检测不出来——那种情况直接进 ③
- **未发现异常 → 路径到此为止**，给描述性总结（趋势+周期+量级），不要硬找问题

### ③ 维度下钻（`dim_rank` → `dim_breakdown`）

异常确认后，定位「谁推动、谁拖累」：

- 先 `dim_rank` 多维对比，挑**分化最明显的维度**（`leading_dim` / `leading_divergence_level`）
- 再 `dim_breakdown` 对该维度单维展开（推动方/拖累方两榜）
- metric_kind 判定见 `data-insight/references/metric-types.md`（本 skill 分支 B
  入口的推导规则只是入口，细节以该文件为准）

### ④ 因子拆解（`formula_breakdown`，ratio/乘法公式类）

维度拆解回答「哪个维度」，因子拆解回答「哪个构成因子」：

- ratio 指标（转化率、客单价）**不得整指标归因**——拆分子分母各自跑序列，
  或写成乘法公式（GMV=访客数×转化率×客单价）交给 `formula_breakdown`（精确 Shapley）
- 维度拆解与因子拆解结论冲突时**都保留**，说明口径差异，不替用户取舍

### ⑤ 解读收口

读结果的规矩与叙述模板在 `data-insight/references/narration.md`（首次归因叙述
前必读）。本路径强制的三条：

1. **先看 self_check.confidence**——low 时不播报数字
2. **net_share_reliable=false 时不用 net_share_pct**（涨跌相抵时数值失真），
   改用 gross_share_pct 分两侧陈述
3. **解释力弱不硬给主因**——「未找到集中解释」+ 量化未解释比例
   （「现有维度解释了 X%，剩余 Y% 尚无对应解释」）

---

## 何时不走完整路径

- 问句是「趋势如何」（无归因诉求）→ 只走 ①
- 问句已指明维度（「是不是华南的问题」）→ ① → ③ 直接单维展开
- 问句是乘法公式的构成变化 → ① → ④
