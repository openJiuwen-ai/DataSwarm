# 检索参数与空结果降级

## 参数说明

```
kb_search(query, kbId?, topK?, agentic?, scoreThreshold?)
```

| 参数 | 含义 | 默认 | 何时调 |
|---|---|---|---|
| `query` | 自然语言查询 | 必填 | 用用户原始问题，不改写成关键词。 |
| `kbId` | 知识库 ID | 默认 `biz_kb` | 多 KB 场景指向具体库。 |
| `topK` | 返回结果数 | 5 | 需要更多候选时调大（如 8-10）；要精简时调小（如 3）。最大 10。 |
| `agentic` | 启用 Agentic 多轮改写检索 | false | 复杂问题、首次检索效果差时开启——检索器会多轮 LLM 改写 query 再融合，召回更全，但更慢。一般不开。 |
| `scoreThreshold` | 相关性分数下限 | 不过滤 | 想过滤低质结果时设（如 0.3）。注意设太高可能过滤掉有用结果。 |

## 默认就够了

大部分场景**只传 `query`** 即可，其余用默认。只有检索效果不理想时才按上表调参，不要一开始就堆参数。

## 结果为空时

`count: 0` 先分清是「库里没内容」还是「有内容但没命中」：

| 返回情况 | 说明 | 下一步 |
|---|---|---|
| `kb_list_entries` 为空 | 库还是空的，属于数据问题 | 引导用户先用 `kb-manage` 入库，调检索参数没有意义 |
| 库有文档但 `count: 0` | 提问措辞和文档用词对不上 | 换一种更贴近文档标题的说法再试 |
| `found: false` | 指定的 `kbId` 不存在 | 确认 `kbId`，或用 `kb_list` 看有哪些库 |

换说法仍没有结果时，再放宽召回参数（`topK` 调大、`scoreThreshold` 留空、`agentic=true`）；一次只动一项，便于判断哪一项起了作用。

全部尝试都为空，就直接告诉用户"知识库里没有相关内容"，不要编造。同一条 query 反复提交不会改变结果，每次重试都要有明确的变化理由。

## score 怎么看

- `score` 是相似度，越高越相关。不同 metric（cosine/ip/l2）下绝对值范围不同，**不要硬编码阈值**判断相关性。
- 经验：top-1 的 score 显著高于其余 → 高置信；多条 score 接近 → 多条都采信并交叉印证。

## 来源引用格式

回答里引用来源时，用 `metadata.file_name`（如 `《订单配置手册.pdf》`）。chunk 级引用可附 `doc_id`，但对外措辞用文档名更友好。

示例：
> 根据知识库中的《报销制度.pdf》，报销流程第三步是提交发票至财务系统。
